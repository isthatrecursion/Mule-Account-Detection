# Audit controls

Business mutations, review history, audit events and their outbox references use the same SQLAlchemy session/transaction. Actor/correlation come from trusted execution context; the audit service supplies UUID/time. Audit failures block business commit. Note/reason references are stored instead of confidential note text; callers must use approved reference identifiers, not embed note bodies in a reference field.

`mule_runtime` can SELECT/INSERT immutable event, approval, label, lineage, score and queue tables, but cannot UPDATE/DELETE/TRUNCATE them. It can UPDATE only workflow fields on cases, status/accepted-validation pointers on batches, lease/state/result fields on jobs and `delivered_at` on outbox. It cannot rewrite case score lineage, outbox payload/audit references, migration history or schema objects. The separate read-only role has SELECT; tracking and operational roles cannot cross-connect. Runtime cannot SET ROLE to the migration role. PostgreSQL integration tests exercise these restrictions through actual runtime credentials.

The migration owner and database/host administrators can alter grants, modify data and perform retention maintenance. Application append-only storage is not cryptographic tamper evidence, and a compromised runtime can still insert fabricated events or bypass service rules through its allowed SQL operations. Administrative maintenance needs a controlled operator/change-ticket log outside application runtime, reviewed before/after hashes and approved retention exceptions. These controls do not claim an external immutable audit sink already exists.

When pilot policy requires tamper-evident retention, export committed audit/outbox events to organization-approved immutable object storage with externally managed retention and integrity manifests; reconcile delivery by stable audit UUID and preserve recorded corrections as new events. The outbox delivery service, external immutable destination, privileged session logging and retention approval must be implemented/validated in deployment and acceptance phases. No local file or self-generated hash can grant pilot/production approval.
